# F6.6 TECHNICAL AUDIT BASELINE

## 1. Rendering Architecture
- **Framework:** Vite SPA (Client-Side Rendering) with React 19 and React Router v7.
- **SSR/Prerendering Status:** The codebase implements an `entry-server.jsx` used by `scripts/test-ssr.js` for architectural validation, but production currently uses `vite build` (CSR). The SSG pipeline is completely architecturally prepared (react-helmet-async hoisted tags, static router compatibility), but the build command does not generate static HTML files for the routes. 
- **Finding:** Googlebot handles CSR well, but INP/LCP will be tied to JS parsing. The architecture is "SSR-ready" for backend integration.

## 2. JS Bundle & Dependencies
- **Total Bundle Size:** ~115 KB (gzipped), 414 KB raw in a single chunk (`index.js`).
- **Route Code Splitting:** Currently disabled. All routes load instantly without Suspense fallbacks. Given the 115 KB size, introducing `React.lazy` right now would likely harm LCP/SEO (due to `Loading...` states) more than it would help performance.
- **Dependencies:** Extremely lean (`lucide-react`, `react-helmet-async`, `react-router-dom`, `tailwindcss`). No duplicated or bloatware packages.

## 3. SEO Metadata & Client-Only Dependencies
- **Implementation:** `<SEO />` component uses `react-helmet-async` context. `useEffect` is NOT used for core SEO metadata, making it immediately available to the virtual DOM and `renderToString`.
- **Finding:** No SEO metadata depends on `window`, `localStorage`, or client-side fetch.

## 4. Image & Font Payloads
- **Heavy Assets:** Several large PNG files (`all-worker-roles.png` 1.9MB, `warehouse-hero.png` 1.8MB) are present in `/public`. These are massive LCP risks for mobile users.
- **Fonts:** Standard system font stacks / basic Tailwind sans are used. No massive webfont blocking chains detected.

## 5. Domain / Brand Leakage
- **Search Results:** `api.gomytruck.com` exists in `EmployerPageTemplate.jsx` and `HeroSection.jsx` for form submissions. This is the correct backend API domain for Parther Technologies and not a domain leakage of the frontend identity.

## 6. Accessibility
- **Semantic HTML:** Pages use proper `<ul>`, `<li>`, and `<section>` tags.
- **H1 Elements:** Verified exactly one H1 per page via `test-geo-content.js`.
- **Anchor Tags:** Internal links use `react-router-dom` `<Link>` elements, which render as standard `<a href="...">` tags, ensuring perfect crawlability.

## 7. URL & Status Codes
- **404 Behavior:** A React-rendered 404 page exists. However, because it's a CSR app served from a CDN, it typically returns a 200 HTTP status code unless the edge/backend explicitly handles it. The React Router `*` catch-all handles visual 404s.

## 8. Scripts & Third-Party
- **Finding:** No heavy third-party scripts (Google Analytics, Intercom) are currently injected into the root HTML that would block rendering.
